Network Maps / Diagrams

Diagrams imported from the legacy system, presented the way the legacy system presents them: pick a group in the tree to open its map. Every device sits on a status marker — a green diamond plate while it is up, a red diamond with a × badge the moment it goes down, amber while its state is not known yet — with its device-type icon, its name, and a type / address caption under it, at the exact position stored in the source database, over the map's own coloured regions and captions. An administrator can also change a map here: Edit Map adds devices to the map (or creates a new device on it), moves a device by dragging it (its links move with it), removes a device from the map without deleting it, and draws or deletes link lines between two devices. Line colour is live: green and flowing while the path is up, red and pulsing when a device on it goes down. Hover a device for its status card; click it to open its full detail and status timeline. On a crowded map, switch on Tidy View (in the map toolbar): the devices are rearranged on screen so that no marker or label overlaps another and the map fits the page cleanly — the stored the legacy system positions are not changed, and switching it off restores them exactly.

Discovered Links — LLDP / CDP / bridge FDB

NetGold walks every SNMP device's neighbour tables (LLDP and CDP, plus the bridge forwarding database — the same correlation classic Layer-2 topology tools use) and finds the real port-to-port links between your monitored devices. ARP data is used only to resolve neighbour identities, never as link evidence by itself.

Legacy Database Import

You are signed in with read-only (viewer) access. Importing changes NetGold's data, so the import controls are available to administrators only.

Direct Import — Recommended

Nothing to type. NetGold looks for the legacy system's SQL Server on this computer, signs in by itself, and shows you the import preview. Imports groups, devices, interfaces, monitor assignments (Ping/Telnet/HTTP/FTP/SNMP) and the network maps/diagrams — devices keep their exact positions from the legacy system's maps.

Imports everything shown in the preview below.

Import from a Backup File (.bak)

Have a backup of the legacy database instead? Type or paste the full path of the .bak file (a browser file picker cannot share real paths, so there is deliberately no picker here). NetGold restores the backup into a temporary database on a SQL Server, imports from it, and deletes the temporary database again.

Important: the backup file path must be a path on the SQL Server computer (or a UNC share the SQL Server service can read) — the SQL Server opens the file, not your browser.

Optional — specify the SQL Server yourself (leave the server blank to use automatic detection):

If the instance uses a dynamic port and the SQL Browser service is stopped, enter the server as HOST,PORT rather than HOST\INSTANCE.

A backup file can only be opened by a SQL Server engine — NetGold uses the SQL Server already on this computer (the one the legacy system installed, or any other local instance), or the server you specify above.

    User Access
    
          
    The portal asks everyone to sign in. There are two kinds of access:
          the administrator (sign-in ID admin) can view and change everything, and a
          viewer sign-in that is read-only — viewers can open every page, download reports and
          view timelines, but cannot change anything. All viewers share ONE sign-in ID and password,
          which only the administrator can set here. Passwords are stored hashed, never in plain text,
          and are never shown again.

    Traffic & Log Collectors
    
          
    NetFlow v5/v9 + IPFIX arrive on UDP -netflow-port (default 2055),
          sFlow on UDP -sflow-port (default 6343), syslog on UDP+TCP -syslog-port
          (default 5514; 0 disables any of them). Flow data is aggregated into 1-minute buckets and kept
          90 days, like the polling samples. On Windows, netgold -service install installs
          NetGold as an automatic Windows service so monitoring continues with no window open; on Linux
          the shipped netgold.service systemd unit does the same.
    
        
    
        
    
          
    Monitoring Defaults
    
          
    Aligned with the legacy system: poll interval default 60 s (allowed range 10 s – 24 h,
          set with the -interval flag); Ping timeout 1 s, 1 retry, 32-byte payload; SNMP timeout
          2 s, 1 retry; TCP service monitors timeout 5 s. Each service monitor can override its own interval,
          timeout and retries on the device page.
